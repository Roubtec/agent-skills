# verify-015-peer-review-run — exercise the retained peer paths and report effective strength

This is a harness-neutral prose check for an agent, not a CI script. Exercise the peer step from your own `review-cycle` rendering, or the byte-identical `review-cycle-core` embedded in `wf-address-tasks.js`, against a non-empty trivial committed change in a scratch worktree. State which harness and provider you exercised; one harness's observation never stands in for the other side.

## Procedure

1. Read the canonical peer block for your harness and follow its retained raw launch shape exactly, including its artifact placement and explicit strength flags. Do not add a model or effort flag of your own.
2. Use the committed prompt guidance: no network access, verbatim thread/diff evidence, and a response that states whether tests were executed or verification was static. Resolve the effective base and review tip to full commit OIDs, create the canonical read-only `diff-evidence.txt` audit copy outside the worktree with that exact `base..tip` log and `base...tip` diff, and construct the prompt through the documented static-heredoc plus literal generated-data contract. Embed both pinned OIDs and the complete audit-copy bytes between `BEGIN EMBEDDED GIT EVIDENCE` and `END EMBEDDED GIT EVIDENCE`; do not ask the provider to read the external file. Require `EVIDENCE_BASE_OID: <full OID>`, `EVIDENCE_TIP_OID: <full OID>`, and `EVIDENCE_TOKEN: <token>`, with an exact distinctive non-whitespace token selected from an added or removed line and occurring exactly once inside the embedded evidence section. Do not reveal an expected token in the prompt.
3. Exercise both evidence-failure branches on disposable copies. For an otherwise valid `passed` artifact, alter an OID proof or remove/replace the token proof; each copy must normalize to `forfeited` with reason exactly `diff evidence unreadable or proof absent`. Repeat with an otherwise valid `issues` artifact: it must remain `issues`, preserve every finding verbatim, and attach that exact reason plus an evidence-failure note.
4. Exercise lifecycle negative controls without targeting a real provider. For the Claude path, use a scratch fake `/proc/<pid>/stat` fixture whose comm contains spaces and `)`, persist the direct provider PID and field-22 start time, then change only that field while retaining the PID number. Every PID probe/signal must treat the changed or missing record as original-process death and record no `kill`; a matching record must target that positive PID only. Force the initial start-time read and identity-file write to fail after the fake provider is live; each must immediately run same-shell direct-PID teardown, prove no survivor, and stop without retrying or advancing. Simulate TERM resistance to observe bounded KILL, then a survivor to confirm the cycle stops. Apply the canonical provider-specific lifecycle controls separately to the retained raw Codex path. Record the result of `node scripts/test-review-cycle-retirement.mjs`, which exercises these controls plus shared-preflight concurrency/reset and workflow-core identity.
5. Confirm the documented deferral: both canonical renderings must retain their raw primary launch until powbox supplies the configured Codex model passthrough tracked in [issue #145](https://github.com/Roubtec/powbox/issues/145) and a documented provider-neutral full-review result such as `reviewFile` or `reviewText`. A path that reads a private filename below `artifactDir` or parses a provider-specific envelope fails this check.
6. Exercise an `unavailable` result where feasible, for example in a deliberately logged-out disposable environment, and confirm it remains non-blocking. Report PASS or FAIL against the provider-specific expectations below and name the other provider as unexercised by this run.

- **Codex peer from the Claude-side rendering and both workflow cores:** inspect the retained raw `codex exec` launch and read `model:` and `reasoning effort:` from its separately captured stderr header. PASS requires the configured high-capability model from `~/.codex/config.toml` and `reasoning effort: medium`; a bare default or `reasoning effort: none` fails. Exercise its canonical PID or process-group lifecycle controls and prove no provider survives the attempt.
