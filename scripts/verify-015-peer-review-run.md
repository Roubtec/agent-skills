# verify-015-peer-review-run — exercise the `peer-review-run` peer paths and report effective strength

This is a harness-neutral prose check for an agent, not a CI script. Exercise the peer step from your own `review-cycle` rendering, or the byte-identical `review-cycle-core` embedded in `wf-address-tasks.js`, against a non-empty trivial committed change in a scratch worktree. State which harness and provider you exercised; one harness's observation never stands in for the other side.

## Procedure

1. Read the canonical peer block for your harness and follow its primary `peer-review-run` launch shape exactly, including its private `artifact_root` placement and explicit strength flags (`--effort medium` on both sides; `--model opus` on the Claude-provider side only). Do not add a model or effort flag of your own. Confirm on the machine you exercise on that the installed helper's `--help` documents `reviewFile` in its result contract and the codex root-`model` passthrough from `${CODEX_HOME:-~/.codex}/config.toml`, and name that build (path and checksum) in the report.
2. Use the committed prompt guidance: no network access, verbatim thread/diff evidence, and a response that states whether tests were executed or verification was static. **The rest of this step and all of step 3 are Claude-provider only** — the embedded-evidence proof contract lives in the Codex-side rendering alone, while the Claude-led skill and both workflow cores launch the Codex provider and carry none of its markers or normalization branches, so a Codex-provider run records them as not applicable rather than failing its canonical launch or inventing noncanonical behavior. Where the Claude provider is what you exercised: resolve the effective base and review tip to full commit OIDs, create the canonical read-only `diff-evidence.txt` audit copy outside the worktree with that exact `base..tip` log and `base...tip` diff, and construct the prompt through the documented static-heredoc plus literal generated-data contract. Embed both pinned OIDs and the complete audit-copy bytes between `BEGIN EMBEDDED GIT EVIDENCE` and `END EMBEDDED GIT EVIDENCE`; do not ask the provider to read the external file. Require `EVIDENCE_BASE_OID: <full OID>`, `EVIDENCE_TIP_OID: <full OID>`, and `EVIDENCE_TOKEN: <token>`, with an exact distinctive non-whitespace token selected from an added or removed line and occurring exactly once inside the embedded evidence section. Do not reveal an expected token in the prompt.
3. **Claude provider only, as above.** Exercise both evidence-failure branches on disposable copies. For an otherwise valid `passed` artifact, alter an OID proof or remove/replace the token proof; each copy must normalize to `forfeited` with reason exactly `diff evidence unreadable or proof absent`. Repeat with an otherwise valid `issues` artifact: it must remain `issues`, preserve every finding verbatim, and attach that exact reason plus an evidence-failure note.
4. Exercise lifecycle negative controls without targeting a real provider. For the Claude path, use a scratch fake `/proc/<pid>/stat` fixture whose comm contains spaces and `)`, persist the direct provider PID and field-22 start time, then change only that field while retaining the PID number. Every PID probe/signal must treat the changed or missing record as original-process death and record no `kill`; a matching record must target that positive PID only. Force the initial start-time read and identity-file write to fail after the fake provider is live; each must immediately run same-shell direct-PID teardown, prove no survivor, and stop without retrying or advancing. Simulate TERM resistance to observe bounded KILL, then a survivor to confirm the cycle stops. Apply the canonical provider-specific lifecycle controls separately to the fallback Codex path. Record the result of `node scripts/test-review-cycle-retirement.mjs`, which exercises these controls plus shared-preflight concurrency/reset, the peer prompt's primary launch shape and degradation route, and workflow-core identity.
5. Confirm the swap: both canonical renderings launch the peer through `peer-review-run` as the primary path, read only the final stdout line of schema `powbox.peer-review-run/v1`, and relay the peer's review as the bytes of the file its `reviewFile` names. A path that reads a private filename below `artifactDir`, parses a provider-specific envelope, or still runs the direct launch while the helper is installed and its result carried a usable `reviewFile` fails this check. Then exercise the degradation route with a stub `peer-review-run` first on `PATH` that emits a `passed` result whose `reviewFile` is `null`: the round must take the manual fallback with the reason `helper result carried no usable reviewFile`, stated once for the run rather than once per round, and a result reporting `model: null` beside a usable `reviewFile` must NOT take it — record it as the applied strength instead.
6. Exercise an `unavailable` result where feasible, for example in a deliberately logged-out disposable environment, and confirm it remains non-blocking. Report PASS or FAIL against the provider-specific expectations below and name the other provider as unexercised by this run.

## Provider-specific observations

- **Claude peer from the Codex-side rendering:** inspect the `peer-review-run --provider claude ... --model opus --effort medium` result. Its reported `model` must be `opus` and `effort` must be `medium`, and the relayed findings must be the bytes of the file `reviewFile` names, with all three `EVIDENCE_*` proof lines present in them. On the fallback `claude -p --model opus --effort medium` launch, the main `modelUsage.canonicalModel` must resolve to an Opus-class model; that raw JSON envelope exposes no effort field, so record effort as unobservable there rather than guessing while separately confirming the explicit `--effort medium` launch flag. Exercise the fallback's direct `$!` PID/start-time identity, PID-reuse refusal, start-read and identity-file-write handoff failures, bounded TERM/KILL, survivor stop, and authoritative verdict artifact after PID death.
- **Codex peer from the Claude-side rendering and both workflow cores:** inspect the `peer-review-run --provider codex ... --effort medium` result (no `--model`). PASS requires its reported `effort` to be `medium` and its reported `model` to be the root `model` of `~/.codex/config.toml` where that file carries one with no root `profile` or `model_provider`; where it does not, `model: null` is recorded as the applied strength and is not a failure, and the helper's stderr names the reason. The relayed findings must be the bytes of the file `reviewFile` names. On the fallback `codex exec` launch, read `model:` and `reasoning effort:` from its separately captured stderr header instead; `reasoning effort: none` fails. Exercise the fallback's canonical PID lifecycle controls and prove no provider survives the attempt.

## Report shape

Report: harness; canonical source exercised (`review-cycle` prose, `wf-review-cycle.js`, or the `wf-address-tasks.js` embedded copy); provider; the helper build confirmed against; the primary launch as run; outcome; `artifactDir` and `reviewFile` from the result; for a Claude-provider run only — reported as not applicable by a Codex-provider one — the diff-evidence audit path and mode, the exact pinned base and tip OIDs quoted from the embedded prompt, the observed `EVIDENCE_TOKEN:`, and the passed and issues outcomes for both mismatched-OID and absent/invalid-token negatives; lifecycle identity/reuse and TERM/KILL/survivor outcomes; concurrent-preflight/reset suite result; observed model; observed effort or explicit raw-Claude unobservability; verification statement (`executed` with commands, or `static`); non-blocking-unavailability result if exercised; the stub-helper degradation result (fallback taken, reason stated once) and confirmation that no private helper artifact below `artifactDir` was consumed; PASS/FAIL; and the provider this run leaves unexercised.
