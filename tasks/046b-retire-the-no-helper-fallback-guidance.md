# 046b — Retire the no-helper fallback prose for the disposable-clone helpers

## Why

Fourteen shipped skill files — seven under `plugins/dev-skills/skills/` and their seven `codex/dev-skills/skills/` mirrors — carry a "where the helper is absent" fallback for `dc-enter`/`dc-remove`. That prose exists once per skill and says roughly the same thing each time, and the skills are already long enough that a rule repeated fourteen times is a real cost.

Measured provenance — re-measured against the current powbox image, which falsified the three-row table this task was originally written on — says the fallback's live audience is every Codex session:

| Consumer | `dc-enter` on PATH? | Why |
|---|---|---|
| Claude on powbox | yes | Claude's plugin runtime puts `plugins/dev-skills/bin/` on PATH — *not* powbox |
| Claude off powbox | yes | the same plugin runtime, and the helpers ship in that tree |
| Codex on powbox | **no** | no plugin runtime, and powbox bakes `gh-review-threads` from this repository but not the `dc-*` pair |
| Codex off powbox | **no** | `codex/` carries only `skills/` — no `bin/`, no install scaffolding |

The measurement behind the two `no` rows: on the current image `/usr/local/bin/dc-enter` and `/usr/local/bin/dc-remove` do not exist, while `/usr/local/bin/gh-review-threads` does and is byte-identical to this repository's copy, and `command -v dc-enter` inside a Claude container resolves under `~/.claude/plugins/cache/` rather than `/usr/local/bin`. Checked helper by helper against the image, the `dc-*` pair is the only helper this repository's own guidance names that the image does not carry — that is the load-bearing fact, and it is the only claim made here about the image's contents.

So the gap is not one off-powbox population that skipped a documented step — it is every Codex session, and a Codex user on powbox is exactly as uncovered as one off it. It remains an *install-state* difference rather than a harness-capability one, and `README.md` documents the remedy today (`mkdir -p ~/.local/bin && install -m 755 plugins/dev-skills/bin/dc-enter plugins/dev-skills/bin/dc-remove ~/.local/bin/`), but the population that has to run that command is every Codex user rather than a stray one, and the fix is landing in the image rather than in this repository's trees.

Two facts bound what this task may claim, and both were measured rather than assumed:

- **The `codex/` tree is not where this gets fixed.** Powbox task 061, in the `Roubtec/powbox` repository — a specification whose own Status section reads "Not started" as of this correction, so everything said of it here is a plan rather than a shipped fact — bakes both helpers into `/usr/local/bin` from this repository's `plugins/dev-skills/bin/` through the same pipe that already bakes `gh-review-threads`, and settles the duplication question in the same breath: a baked copy for Claude alone "would create two artifacts to keep in sync for no gain. The baked copy serves both." A copy under `codex/dev-skills/bin/` would be a third. Shipping `bin/` into `codex/` would not put it on PATH by itself either — Codex has no equivalent of Claude's plugin runtime; the tree is files in a config folder — so it would buy a self-contained tree at the price of a mirror to keep in sync, with the manual PATH step surviving either way.
- **This retirement covers the plugin-shipped helpers only.** Any helper that is baked into the powbox image rather than shipped from this repo keeps its fallback, because a container on an older image genuinely lacks them and their fallbacks stay reachable. Task 046 widened one such fallback (the Cleanup pre-removal marker list) precisely because it is reachable. Do not delete those.

`gh-review-threads` is settled and needs no drift check: powbox sources it directly from this repo and its CI smoke tests assert the script's presence.

## Scope amendment

The provenance table above was corrected against measurement after this task was written, and the powbox counterpart was located. Two parts of the original scope are withdrawn or deferred as a result; the rest stands.

**Withdrawn — acceptance criterion 1, shipping `bin/` into `codex/`.** Do not create `codex/dev-skills/bin/`. Powbox task 061 in the `Roubtec/powbox` repository bakes both helpers for both flavors from this repository's `plugins/dev-skills/bin/`, on the settled ground, stated there, that a baked copy for Claude alone would create "two artifacts to keep in sync for no gain" and that the one baked copy serves both flavors. A `codex/` copy would be the third artifact, and would contradict the one-source-of-truth rule that repository's architecture chapter encodes for vendored baked helpers.

**Deferred — the single stated precondition and the per-skill deletions.** Both are gated on a rebuilt powbox image actually carrying the helpers, not merely on powbox task 061 merging. That task's implementation notes state: "Do not add a fallback path for containers built before this lands. The consumer wording that 017 owns already degrades on `command -v`, which is the whole point of that clause." Containers built before it lands are a population that outlives its merge, which is why the gate here is the image rather than the merge, and powbox 061 relies on this repository keeping the fallback until then. Landing the precondition and the deletions early would not degrade *silently* — the precondition's whole point, stated under "What to do", is that a missing helper stops with a message naming the install step — but it would stop **every** Codex session on every container whose image predates the bake, until its operator runs that install step by hand. Buying off that stop is what the gate is for. Once a rebuilt image carries `/usr/local/bin/dc-enter` and `/usr/local/bin/dc-remove`, the precondition and the deletions land on a new branch for this task.

**The deferred sweep's real surface is larger than the fourteen skill files, and a shipped suite guards it.** The same rule ships in the dynamic workflows too, spelled "Where the helper is absent, use an absolute path outside the repository — never a relative one, and never the repository itself." — `plugins/dev-skills/workflows/wf-address-tasks.js` carries it at two sites, `wf-review-cycle.js` at two, and `wf-address-review.js` at one. Those five sites are **in** the deferred sweep: a precondition stated once cannot coexist with a fallback the workflows still render into every subagent prompt they compose. And `scripts/test-subagent-destroy-boundary.mjs` anchors that exact sentence as a deletion guard — the `REQUIRED` clause table's `absolute-path fallback` entry, whose surrounding commentary argues that the fallback's phrase must span its condition and verb precisely so a copy cannot waive it. So deleting the clause turns that suite red by design, and the retained criterion that every suite named in `.github/workflows/tests.yml` passes is what forces the guard entry and its commentary to be updated in the same change. The skill files spell the same rule slightly differently ("name an absolute path" rather than "use an absolute path") and are not themselves guarded by that entry, so a sweep that stopped at the fourteen would leave the workflows contradicting the new precondition while the suite stayed green — which is the outcome this paragraph exists to pre-empt.

**Delivered ahead of that gate:** the corrected `codex/` bullet in `README.md` — every Codex session needs the documented `install` step today, not only a Codex user off powbox — the `DC_ROOT` sentence in the `dc-enter`/`dc-remove` bullet, which predicted powbox would set the variable and named `$TMPDIR` as the only default, and this correction to the task file itself. The same prediction ships in `plugins/dev-skills/bin/dc-enter`'s own header, in the comment block containing "`DC_ROOT` is the placement interface"; correcting a shipped helper is out of this task's scope, so task 046d carries it.

## What to do

- **Now:** correct `README.md`'s `codex/` bullet so it states that every Codex session needs the documented `install` step, keeping the install command and the `mkdir -p` rationale sentence, both of which are correct and load-bearing, and stating powbox's baking of `gh-review-threads` but not the `dc-*` pair as the observed fact it is rather than as a forecast of what powbox will do next.
- **Now:** correct the `DC_ROOT` sentence in `README.md`'s `dc-enter`/`dc-remove` bullet to the resolution order the helper actually implements — an optional absolute-path override, else `$TMPDIR`, else `/tmp` — instead of predicting that powbox will set it. Say nothing there that the helper's own header contradicts; the header's matching prediction is task 046d's to remove.
- **After a rebuilt powbox image carries `/usr/local/bin/dc-enter` and `/usr/local/bin/dc-remove`** — the image, not powbox task 061's merge; see "Scope amendment" for why: state the helpers as a **precondition** in one place rather than as a fallback in fourteen: the skills may assume `dc-enter`/`dc-remove` are on PATH, and a run that finds them missing stops with a message naming the install step instead of degrading into a hand-rolled path.
- **After that same rebuilt image carries them:** remove the "Where the helper is absent, name an absolute path outside the repository" prose from all fourteen skill files once that precondition exists, and the five workflow sites of the same rule named in "Scope amendment" with them, keeping the destroy boundary's *destination* rule itself intact — what goes is the branch for the helper being absent, not the requirement that empirical verification happens in a disposable clone. Update `scripts/test-subagent-destroy-boundary.mjs`'s `absolute-path fallback` guard entry and the commentary that justifies it in the same change; the suite is written to fail on that deletion.
- Leave every fallback for an image-baked helper untouched, and say so in the PR description so the sweep's boundary is checkable rather than asserted.

## Considered and declined

**Move the no-helper guidance into a separate file referenced only by the Codex-flavored skills.** Rejected for two reasons that stand together. The first is what this task is *for*: the end state under "What to do" is a single precondition that stops and names the install command, so a shared file would centralize — and thereby invest in — exactly the fallback behavior being retired, while splitting one contract across two documents for a branch already scheduled for deletion. The second is the axis. The two flavors are kept in lockstep and diverge only where *harness capabilities* differ, whereas a missing helper is an *install-state* difference; flavor is only today's correlate of it, not its cause, and powbox task 061 loosens even the correlation by giving a rebuilt image's Codex sessions the helper. It does not make Codex-keyed guidance false — the guidance is itself conditional on `command -v`, so it stays harmlessly applicable to a Codex session off powbox or on an older image — but it does make the flavor a worse and worsening proxy for the thing the guidance actually turns on.

The reason originally given here — "the same Codex user on powbox has the helper on PATH" — rested on the falsified table and is false today, since a Codex user on powbox has no `dc-enter` either.
